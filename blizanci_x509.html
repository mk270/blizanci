    cert_key_match(CertFile, KeyFile)

    Check that a PEM certificate file and a PEM private key file are a matching pair, so that a server using them can complete a handshake. The certificate is the first one in its file (the leaf, when the file holds a chain); the key is the first private key in its file, which may be the same file. RSA keys match on modulus and public exponent; EC keys (P-256, P-384, P-521) on the public point derived from the private scalar, which must be on the same named curve; Ed25519 and Ed448 likewise.     cert_key_match(CertFile, KeyFile)

    -spec cert_key_match(CertFile, KeyFile) -> Result
                        when
                            CertFile :: string(),
                            KeyFile :: string(),
                            Result :: ok | {ok, unverified, Reason} | {error, term()},
                            Reason :: {unsupported_key_type, string()}.

    Check that a PEM certificate file and a PEM private key file are a matching pair, so that a server using them can complete a handshake. The certificate is the first one in its file (the leaf, when the file holds a chain); the key is the first private key in its file, which may be the same file. RSA keys match on modulus and public exponent; EC keys (P-256, P-384, P-521) on the public point derived from the private scalar, which must be on the same named curve; Ed25519 and Ed448 likewise. Nothing is trusted from the file's own idea of the public key. PKCS#1, PKCS#8 and SEC1 containers are all handled.

    Result is ok for a verified match; {ok, unverified, Reason} for a pair the check cannot compare, where Reason is {unsupported_key_type, Name} (Name a string such as "DSA" or "EC secp224r1"), which is NOT a failure and the caller should warn; {error, mismatch} for a pair that provably does not match; or {error, {certfile, Why}} / {error, {keyfile, Why}} for a file problem, which names the file at fault: {unreadable, Posix}, no_certificate_in_file or certificate_not_decodable (certfile), {unreadable, Posix}, no_private_key, encrypted_private_key or private_key_not_decodable (keyfile).

    The rule: each side's family is RSA, EC (any curve, Ed25519 and Ed448 included) or DSA when we can tell. Two different families are a mismatch, even if one is a family we cannot compare, so an RSA certificate with a DSA key is refused. Within RSA, and within EC on the supported curves, the keys are compared. Two EC keys on different named curves are a mismatch. Otherwise (DSA with DSA, the same unsupported EC curve, RSA-PSS or any other algorithm we do not know, on either side) the pair is unverified.

    check_cert(DerCert)

    -spec check_cert(DerCert) -> Result
                    when
                        DerCert :: public_key:der_encoded(),
                        Result ::
                            {ok,
                             #'OTPCertificate'{tbsCertificate :: term(),
                                               signatureAlgorithm :: term(),
                                               signature :: term()}} |
                            {error, cert_expired} |
                            {error, cert_not_yet_valid} |
                            {error, cert_not_parsed}.

    Decode a raw client certificate and check that the current time falls within its validity period (NotBefore/NotAfter).

    As with peercert_cn/1, the input is remote-attacker-controlled, so a certificate we can't decode at all is reported distinctly (cert_not_parsed) from one which decodes fine but is outside its validity period: past NotAfter (cert_expired) or before NotBefore (cert_not_yet_valid).

    peercert_cn(C)

    -spec peercert_cn(C) -> ClientCert when C :: term(), ClientCert :: client_cert_details().

    Check if the connection has a valid certificate, and return the issuer and subject names, or error.

    A certificate is remote-attacker-controlled input: decoding it, or dumping its RDNs, must never crash the calling process. Any failure is reported as a distinct {error, Reason}, distinguishing a certificate we plain couldn't decode (cert_not_parsed) from one which decoded fine but uses a directory-string encoding for an RDN attribute value that we don't know how to render (cert_unsupported_encoding), e.g. bmpString/universalString.

    A certificate with no Common Name is not an error: the corresponding value in the result is the atom undefined (for the subject, the issuer, or both).

    verify_signed_by(DerCert, IssuerCert)

    -spec verify_signed_by(DerCert, IssuerCert) -> Result
                          when
                              DerCert :: public_key:der_encoded(),
                              IssuerCert ::
                                  #'OTPCertificate'{tbsCertificate :: term(),
                                                    signatureAlgorithm :: term(),
                                                    signature :: term()},
                              Result :: boolean().

    Check that DerCert was actually signed by IssuerCert's private key -- a genuine cryptographic check, not the name-comparison that public_key:pkix_is_issuer/2 does (that function only compares the Issuer field of DerCert against the Subject field of IssuerCert; it is meant for candidate-chain construction, not a standalone trust decision, and is trivially spoofable by anyone able to set those fields on a self-signed certificate).

    Deliberately minimal: this does not require IssuerCert to be a "proper" CA certificate (no basicConstraints/keyUsage checks, unlike public_key:pkix_path_validation/3) -- blizanci's issuer certs are used the way an organisation runs its own internal CA for e.g. mail/VPN clients, not as web-PKI CAs, and may not carry those extensions.
