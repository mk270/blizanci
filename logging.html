    Logging

    The module blizanci_log provides runtime log-level control for blizanci.

    The OTP logger has two filtering layers: a primary (global) level that gates all log events before they reach any handler, and a per-handler level that controls what each handler actually emits. blizanci_log:level/1 sets both together so the observable behaviour is straightforward.

    The application sets no log levels itself; they come from the node's kernel configuration. With no logger or logger_level key, the primary level is notice and the default handler's level is all; blizanci_log:module_level/2 then makes a module's debug events appear, provided they are logged with the logger macros (?LOG_DEBUG and the like), since a plain logger:debug/1 call carries no module for the override to match. With the example configuration (logger_level debug but the default handler at info), the primary level is debug and the handler level info, so module_level/2 alone prints nothing; the handler level must be lowered too, as level/1 does for both.

    The warnings and errors mentioned elsewhere in this manual (start-up errors, old-format and shadowed routes, unverifiable certificate pairs) are all logged through the OTP logger; see the Configuration and Routing chapters.
